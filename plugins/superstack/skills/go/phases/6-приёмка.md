## Фаза 6 — СЛЕПАЯ ПРИЁМКА

Всё до сих пор сверялось со спекой, то есть с твоим же пересказом просьбы.

Изменения собери с именами файлов КАК ЕСТЬ. По умолчанию имя с кириллицей
приезжает закодированным, и границу файла приходится узнавать в самой хрупкой
форме на каждом прогоне — а `ТЗ.md` и `Требования.md` тут норма, а не редкость:

```bash
git add -N .
git -c core.quotepath=false diff HEAD > .superstack/изменения.diff
python3 "$CLAUDE_PLUGIN_ROOT/tools/blind_accept.py" pack .superstack/<дата>-brief.md .superstack/изменения.diff
```

Первая строка нужна ради новых файлов: без неё их в изменениях не будет вовсе,
а новый код — это чаще всего именно они. Содержимого она никуда не переносит,
только показывает, что файл появился.

Пакет отдай агенту `blind-acceptance`: он видит просьбу и изменения, и **ничего
больше**. Вердикт по каждому требованию запиши в `blind` манифеста.

**Гейт G4** — манифест не имеет права утверждать то, что независимая проверка
отрицает:

```bash
python3 "$CLAUDE_PLUGIN_ROOT/tools/gates.py" .superstack/manifest.json --gate G4
```

Сойтись можно в обе стороны — починив сборку или честно понизив строку. Нельзя
только умолчать. Расхождение здесь — не провал прогона, а его работа.

### Расхождение, которое решает человек, — тоже повод его позвать

Если гейт G4 не сошёлся и выбор «чинить или честно понизить строку» не
очевиден без его слов — дальше стоит именно его решение, а не код. Он мог не
следить за этим прогоном прямо сейчас:

```bash
python3 "$CLAUDE_PLUGIN_ROOT/tools/notify.py" . --text "приёмка нашла расхождение, нужен твой выбор"
```

Зови, только когда решение действительно за ним — расхождение, которое
чинится очевидным способом самим кодом, звонка не стоит.
